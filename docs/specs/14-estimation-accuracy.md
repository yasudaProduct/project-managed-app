# 見積精度分析 仕様書

## 1. 概要

完了タスクの実績工数を基準工数と比べ、「どの工程で見積がずれやすいか」を示す画面（`/estimation-accuracy`、サイドメニュー「見積精度」）。Q7「次のプロジェクトに何を活かすか」に答える。

関連: [要件整理 3-2](../plans/progress-management-analysis-requirements.md)

## 2. 対象

- 中止（CANCELLED）以外のプロジェクトの最新 WBS（振り返りが目的のため、完了済みプロジェクトも含める）
- そのうち、状態が完了で論理削除されていないタスク（未完了タスクの実績は途中のため比べない）

## 3. 集計

| 値 | 定義 |
|---|---|
| 基準工数 | 基準（KIJUN）の通常工数。基準未設定のタスクは予定（YOTEI）の通常工数で代用（EVM の BAC と同じ扱い） |
| 実績工数 | タスクに紐付く作業実績の合計 |
| 実績 / 基準 | 実績工数の合計 ÷ 基準工数の合計。100% を超えると見積より多くかかった（赤字）。基準の合計が0なら「—」 |
| 超過タスクの割合 | 実績工数が基準工数を上回った完了タスクの割合 |

集計単位:

1. **工程テンプレート別（プロジェクト横断）**: 工程テンプレート（`PhaseTemplate`）でまとめる。テンプレート未設定の工程は工程名でまとめ、工程未設定のタスクは「未分類」
2. **プロジェクト × 工程別**: 「プロジェクト名 / 工程名」ごと

あわせて全体（完了タスク数・実績 / 基準）を表示する。集計ロジックは `src/domains/estimation/estimation-accuracy.ts`。

## 4. 実装

複数プロジェクトを横断する読み取り専用の集計のため、CQRS（`GetEstimationAccuracyQuery` → `GetEstimationAccuracyHandler`、QueryBus に登録）と専用の QueryRepository（`EstimationAccuracyQueryRepository`）で実装する（docs/04 の CQRS 適用基準）。
