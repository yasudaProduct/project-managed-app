# データの鮮度 仕様書

## 1. 概要

「この数字は信用できるか」を判断するため、WBS のサマリータブと EVM タブに「データの鮮度」を表示する（`src/components/wbs/data-freshness-panel.tsx`）。

関連: [要件整理 1-4](../plans/progress-management-analysis-requirements.md)

## 2. 表示内容

| 項目 | 内容 | データ元 |
|---|---|---|
| WBS同期 | 最後に WBS を同期した日時と結果（成功／一部失敗／失敗）。履歴がなければ「履歴なし」 | `SyncLog`（プロジェクト単位の最新） |
| 実績（月報）の入力漏れ | 直近10営業日（前日まで）で入力漏れのある担当者・最終入力日・入力漏れの日 | `WorkRecord`（全 WBS 横断）、`UserSchedule`、会社カレンダー |
| タスクデータの不備 | 担当者未設定・基準工数未設定・着手中で進捗率0% の件数（0件は表示しない） | 有効タスク |

## 3. 実績の入力漏れ

作業者は月報を毎日入力する運用のため、次の条件をすべて満たす日を入力漏れとする（`src/domains/work-record/missing-work-entry.ts`）。

1. 営業日（土日・祝日・会社休日を除く）
2. 確認期間内：前日（JST）から遡って10営業日
3. その担当者が担当するタスクの予定（YOTEI）期間に含まれる日（両端含む）
4. 全日休暇の予定がない日（予定タイトルが「休暇」「有給」等。`FULL_DAY_OFF_TITLES`）
5. 実績時間の合計（**全 WBS 横断**）が0時間の日

- 他案件の作業を入力した日は入力済みとみなす（全 WBS 横断で合計するため）
- 最終入力日は、今日以前で実績時間が0より大きい最後の日（全 WBS 横断）
- 対象の担当者は WBS 担当者（`WbsAssignee`）。タスクとの対応はユーザーID（`Users.id`）で取る
- 実績は Geppo 取込後に `WorkRecord` に入るため、取込が止まっていると全員が入力漏れに見える。その場合は全員の最終入力日が同じ日に揃うことで気づける

## 4. タスクデータの不備

| 項目 | 条件 | 影響 |
|---|---|---|
| 担当者未設定 | 担当者がいない | 通知・入力漏れ確認の対象外になる |
| 基準工数未設定 | 基準（KIJUN）の通常工数がない、または0 | EVM の BAC が予定工数にフォールバックする |
| 着手中で進捗率0% | 状態が着手中で進捗率が0または未入力 | 自己申告進捗率方式で EV が0になる |

## 5. データ取得

`getDataFreshness`（`src/app/wbs/[id]/actions/data-freshness-actions.ts`）→ `DataFreshnessApplicationService`。WBS 画面・プロジェクト画面の表示時にサーバー側で取得する。
