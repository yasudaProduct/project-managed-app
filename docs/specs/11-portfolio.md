# ポートフォリオ一覧 仕様書

## 1. 概要

組織として「どのプロジェクトが危ないか」を一覧で把握するための画面（`/portfolio`、サイドメニュー「ポートフォリオ」）。管理者・PMO が個別の WBS を1つずつ開かずに状況を把握できるようにする。

関連: [要件整理 3-1](../plans/progress-management-analysis-requirements.md)

## 2. 対象

未開始（INACTIVE）・進行中（ACTIVE）プロジェクトの最新 WBS（プロジェクトごとに1件。担当者負荷の横断集計と同じ `ITargetWbsQueryRepository`）。

## 3. 表示項目

| 項目 | 内容 | 計算元 |
|---|---|---|
| ヘルス | 危機的／注意／健全／開始前 | EVM（しきい値は各プロジェクトの設定） |
| SPI / CPI / 出来高率 | 現在値 | EVM |
| 予測完了日 | Earned Schedule による予測完了日と、計画終了日に対する遅れ（前倒し）日数 | EVM のスケジュール予測 |
| EAC / VAC | 完了時の工数予測と、BAC との差 | EVM（予測方式は各プロジェクトの設定） |
| 遅れタスク | 終了遅れ・開始遅れの件数 | 遅延タスク判定（[09-task-delay](./09-task-delay.md)） |
| 入力漏れ | 直近10営業日に実績の入力漏れがある担当者数 | データの鮮度（[10-data-freshness](./10-data-freshness.md)） |
| WBS同期 | 最終同期日時 | データの鮮度 |
| 悪化傾向 | SPI / CPI が進捗確認サイクルの単位で3期連続して悪化していれば「SPI悪化」「CPI悪化」 | 悪化トレンド（[02-evm 付録「悪化トレンド」](./02-evm.md)） |

- 値は工数（h）。進捗測定方式・予測方式は各プロジェクトの設定に従う
- 計算は各画面と同じ Application Service（`EvmService.getEvmSummary`・`TaskDelayApplicationService`・`DataFreshnessApplicationService`）を組み合わせて行い、個別画面と数字が食い違わないようにする
- `getEvmSummary` は現在メトリクスとスケジュール予測だけを求める軽量版（時系列は計算しない）

## 4. 並び順

危ない順：ヘルスが 危機的 → 注意 → 健全 → 開始前、同じヘルスの中は SPI の低い順。

## 5. エラー時

1件のプロジェクトの取得に失敗しても他の行は表示し、失敗した行には「データを取得できませんでした」と表示する。

## 6. 制約・今後の課題

- プロジェクト数に比例して表示が遅くなる（各プロジェクトのタスク・実績を都度読む）。件数が増えたら集計結果のキャッシュを検討する
